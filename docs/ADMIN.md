# 本地任务管理后台

Issue #6 将 Task/Run 管理 API 接成独立 React + Vite 页面，默认从 `http://127.0.0.1:3000/admin/` 访问。先在根目录安装依赖、`npm run build`、配置管理 Token 与 Codex 登录，然后启动 Backend。详细部署见 [Linux 部署第 12 节](DEPLOY_LINUX.md#12-issue-6-本地管理后台)。

## 操作路径

1. 输入服务端已配置的管理 Token。Token 不保存在浏览器持久存储、Cookie、URL 或构建产物中；刷新需重新输入。
2. 任务总览显示已配置任务、最新执行状态、最近异常与最后触发时间。没有调度执行，配置中的 schedule 仅只读展示。
3. 选择任务查看配置、提示词和分页 Run 历史（每页 20 条）。手动执行会调用真实 Codex、使用账户额度；执行中禁用重复提交，网络异常后的页面内重试复用原幂等键。
4. 从任务进入 Run，查看状态、创建/开始/结束时间、Thread/Turn ID、分页事件日志（每页 100 条）和 Turn 输出。没有独立 Agent 工作台；路由检查 Run 属于当前 Task。
5. 新闻 Run 成功后可查看日报，包含分类、重要性、来源事实摘要、分析（推断）、精确引文、原文链接与三类时间；未知时间显示未知。格式与来源关联通过仍是待人工审核，不代表独立证实。样例或未生成报告明确显示空状态。

## 刷新、认证与失败

服务端历史持久化在 SQLite，hash 路由保留 Task/Run 定位；刷新后重新认证可继续查看。退出、Token 失效或管理 API 关闭时移除私有视图。Codex 认证错误属于 Run 执行错误，与管理 Token 登录失效分开展示。

每 2 秒顺序轮询，不并发叠加同一页面的请求；切换页面或退出会中断请求并忽略迟到响应。网络/服务错误显示提示，已有数据显示时保留并标注失败，轮询自动重试。手动提交不会自动重试；明确的 4xx 可重新生成键，网络不确定时复用原键。刷新会丢弃页面内提交键，因此网络不确定时应先在历史中确认原 Run，避免盲目再次执行。

Issue #7 已增加报告人工批准与 GitHub 归档：先核对来源、时间、事实摘要与推断并勾选确认，再批准此版本，最后单独归档。目标必须由服务配置提供，默认关闭；成功展示 SHA，失败可显式重试。见 [发布说明](PUBLISHING.md)。当前不支持任务编辑、定时调度、继续 Turn、取消按钮、Agent 工具交互审批或 SSE。管理后台不是公开阅读站，禁止将 `dist/admin` 加入 Cloudflare Pages 公共产物。页面壳可以未登录加载，实际私有数据/写操作均受 Backend Bearer Token 保护；不在静态文件内嵌入服务 Token。

## 检查

`npm run lint`、`npm run typecheck`、`npm test`、`npm run build` 在根目录运行。测试包含后端入口/静态路径边界、认证与错误状态、Task → Run、重复点击、迟到响应取消、会话失效与安全报告预览。`npm run test:admin` 可单独运行交互测试，不访问真实模型。
