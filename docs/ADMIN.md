# 任务管理界面更新

任务总览以用户配置任务为主：新增/编辑配置主题、多轮 Prompt（可排序）、手动/单次/周期计划、时区与自动发布；列表提供立即启动、停止执行、启停任务和确认删除。删除保留历史。执行记录和各轮结果统一在“运行与结果”查看，不需交互式追问。旧预定义任务不在任务列表展示，数据库历史保留。详见 [任务管理](TASK_MANAGEMENT.md)。

# 本地任务管理后台

Issue #6 将 Task/Run 管理 API 接成独立 React + Vite 页面，默认从 `http://127.0.0.1:3000/admin/` 访问。先在根目录安装依赖、`npm run build`、完成管理员初始化与 Codex 登录，然后启动 Backend。详细部署见 [Linux 部署第 12 节](DEPLOY_LINUX.md#12-issue-6-本地管理后台)。

## 操作路径

1. 首次页面只填写“设置密码”和“确认密码”，无需初始密码或复制码；之后用密码登录。旧 Token 迁移用户可先用旧 Token 登录再改设密码。临时会话不保存在浏览器持久存储、Cookie、URL 或构建产物中；刷新重新登录。
2. 登录后进入系统概览，查看任务、执行、待审核和近期趋势。任务总览使用紧凑表格管理任务主题、执行计划、下次执行、最近状态和自动发布，可新增、编辑、启动、停止、启停定时和确认删除。
3. 选择任务查看配置、提示词和分页 Run 历史（每页 20 条）。手动执行会调用真实 Codex、使用账户额度；执行中禁用重复提交，网络异常后的页面内重试复用原幂等键。
4. 从任务进入 Run，默认查看研究会话；“执行日志”提供分页事件（每页 100 条），“运行信息”提供创建/开始/结束时间、Thread/Turn ID 和原始 Turn 输出。没有独立 Agent 工作台；路由检查 Run 属于当前 Task。
5. 新闻任务填写主题和初始 prompt 开始 Run；在 Run 页面查看每轮原始 prompt/回复，输入下一轮 prompt 点击“继续研究”或“生成待审核日报”。一个 Run 最多 20 轮，生成成功后固定；失败可修正重试。
6. 显式生成成功后可查看日报，包含分类、重要性、来源事实摘要、分析（推断）、精确引文、原文链接与三类时间；未知时间显示未知。格式与来源关联通过仍是待人工审核，不代表独立证实。样例或未生成报告明确显示空状态。

## 页面布局

后台采用浅色工作台：桌面侧栏、任务状态列表、研究表单与会话主区；窄屏保留顶部任务/设置/退出导航，辅助区转为单列。研究会话、执行日志和运行信息通过标签切换，输入草稿与待重试请求不会因切换标签或日志翻页丢失。标签可用方向键、Home/End 操作。

系统设置按模型与执行、GitHub 归档、管理员密码分组，分区导航滚动定位到对应表单。登录页仍区分首次设置、密码登录和旧 Token 迁移。样式、图标使用本地产物，无远程字体或图片依赖。视觉约定见 [UI 规范](UI_DESIGN_SPEC.md)。

## 刷新、认证与失败

服务端历史持久化在 SQLite，hash 路由保留 Task/Run 定位；刷新后重新认证可继续查看。退出、Token 失效或管理 API 关闭时移除私有视图。Codex 认证错误属于 Run 执行错误，与管理 Token 登录失效分开展示。

每 2 秒顺序轮询，不并发叠加同一页面的请求；切换页面或退出会中断请求并忽略迟到响应。网络/服务错误显示提示，已有数据显示时保留并标注失败，轮询自动重试。手动提交不会自动重试；明确的 4xx 可重新生成键，网络不确定时复用原键和完整 payload，锁定输入并提供“重试原请求”。刷新会丢弃页面内提交键，因此网络不确定时应先在历史中确认原 Run，避免盲目再次执行。

Issue #7 已增加报告人工批准与 GitHub 归档：先核对来源、时间、事实摘要与推断并勾选确认，再批准此版本，最后单独归档。目标在后台“GitHub 归档”填写并保存到数据库，默认关闭；成功展示 SHA，失败可显式重试。更换目标后需明确执行归档；已有当前目标成功记录的刷新只读本地记录。见 [发布说明](PUBLISHING.md)。支持用户任务定义编辑、定时计划与停止执行；仍不支持 Agent 工具交互审批或 SSE。管理后台不是公开阅读站，禁止将 `dist/admin` 加入 Cloudflare Pages 公共产物。页面壳可以未登录加载，实际私有数据/写操作均受 Backend Bearer Token 保护；不在静态文件内嵌入服务 Token。

## 检查

`npm run lint`、`npm run typecheck`、`npm test`、`npm run build` 在根目录运行。测试包含后端入口/静态路径边界、认证与错误状态、Task → Run、重复点击、迟到响应取消、会话失效与安全报告预览。`npm run test:admin` 可单独运行交互测试，不访问真实模型。

## 系统设置

登录后点击“系统设置”，保存 Codex 路径/模型、执行超时/并发/队列、日志和 GitHub 归档目标。设置写 SQLite，空闲时立即生效；执行/排队/归档中拒绝修改。页面展示 revision 冲突错误，不自动覆盖其他页面修改。

GitHub Token 不回显；留空保留原值、输入新值替换、勾选清除显式移除。设置管理员密码时须验证当前密码或旧 Token，成功切换当前会话并撤销其他会话。保存设置不会触发模型或发布。`.env` 仅保留监听地址/端口/数据目录，详见 [设置说明](SETTINGS.md)。

<!-- Settings UI update -->
管理后台侧栏平级显示任务总览、模型与执行、GitHub 归档、安全设置，不再设置父级菜单；右侧单列显示当前标题与表单，窄屏导航折为顶部菜单。切换前需保存当前修改。Token 始终显示空白密码输入框；留空保存保留已有凭据，输入新值才替换；没有单独的设置/更换按钮或清除复选框。分支无预填值；已有配置保留。更新前端需运行 `npm run build`。

管理后台移除重复页名顶栏与静态“本地管理/A”标识；每页只保留内容标题，设置表单使用侧栏外的可用宽度。运行详情保留返回任务入口。更新后台后需刷新页面加载新静态资源。

任务新增/编辑使用独立模态卡片，表单内部滚动；保存或取消返回任务列表，编辑时不在列表上方展开表单。

任务配置与执行结果分开：任务总览负责配置、计划和启停；独立“运行与结果”提供跨任务历史、任务/状态筛选及分页，包含已删除任务的历史。详情默认展示最终日报，Prompt 输出和日志为次级标签，支持审核与发布。不再追加系统生成 Prompt，最后一条配置直接生成日报；历史来源抓取失败记录保留可查；新执行不再抓取原文。



“运行与结果”的所属任务筛选仅列出用户配置任务；内置研究/诊断任务不作为选项，已有运行历史仍保留在全部记录中。

当前日报来源模式为 `codex_reported`：Backend 不再联网核验原文或匹配引文，不再追加来源修复；保留 JSON/HTTPS 链接格式、数据关联和发布哈希检查。后端未抓取时 `fetchedAt/fetched_at` 为 null，不伪造原文发布时间或事件时间。历史 `source_only` 报告仍可读取和归档。

当前用户配置任务严格执行 N 条 Prompt = N 次 Codex Turn。最后一条原始 Prompt 直接返回日报结构，Backend 只在开发者格式指令中提供主题/时间/Schema，不改写持久化的用户 Prompt，也不再追加“依据前面所有轮次的研究结果，生成完整日报。”。旧执行记录的额外系统轮仅作为历史保留。

每轮执行超时的新安装默认值为10分钟；管理后台按分钟显示和编辑，Backend/API/SQLite保持毫秒存储，已有自定义值不被重置。

最终结果以固定 HTML 模板呈现为简报阅读预览：编号、中文分类、正文、可选分析和原文链接；引文及已知来源时间折叠展示，缺失日期与空分析隐藏，结构化 JSON 可展开。审核和 GitHub 归档操作保留在预览之外；仅调整展示，不增加 Codex 调用、不改写保存的结果或归档数据。

## 系统概览

首页 `/admin/#` 与任务管理 `/admin/#/tasks` 分开。统计来自认证接口 `GET /api/overview`，每 10 秒刷新；加载失败显示错误，零数据有独立空状态，不填充示例数据。图表附可展开的每日数据表，可直接查看准确数字。点击指标或待处理入口进入任务管理或相应状态的运行列表。

- 当前任务：仅未删除的用户配置任务，分为手动、定时已启用、定时已暂停；暂停任务仍支持手动运行。
- 今日/近 7 天：上海时区自然日，包含今天和前 6 天，按运行创建时间归组；包含已删除配置任务的历史，不含内置研究/诊断运行。
- 执行趋势：成功、失败、停止/中断、执行/排队分别统计。成功率分母仅为成功与失败次数；无已完成样本显示“—”。
- 正在运行：执行/等待工具审批或归档中的运行，排队单列提示。
- 待审核、待归档、归档失败：复用运行列表的最新报告/归档状态判断；不会将自动归档前置失败误计为待审核。
- 近 7 天异常/中断包含失败、取消、中断。对应入口打开完整异常历史；今日执行卡片也打开完整运行历史，日期范围仅用于概览统计。
- 最近执行：最新 5 次配置任务运行，耗时为开始至结束，不含排队时长；未开始显示“—”。

任务管理支持主题搜索、手动/定时启用/定时暂停筛选及每页 10 条分页，仅查询当前页任务的最新执行状态。桌面使用紧凑表格，窄屏使用任务卡片，编辑为行内操作，删除仍需确认。任务列表和配置详情不再提供“运行记录”快捷入口，执行历史统一在“运行与结果”查看；单页列表隐藏翻页按钮。

GitHub 归档不再设全局启用开关：仓库、分支和已保存 Token 完整即为可用；允许保存未完整配置，清除凭据后恢复未配置。旧 `github.enabled` 写入参数为可选兼容字段且被忽略，返回值表示派生配置状态，旧数据库中的 false 不再禁用完整目标。任务 `autoPublish` 继续独立控制自动归档。建议创建 fine-grained PAT，仅选择归档仓库并授予 Contents read/write；后台不展示已保存 Token。
