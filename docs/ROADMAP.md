# 开发路线图

> 所有条目均为**计划事项**，不是完成情况。优先建立可以真实运行的最小闭环，再逐步扩充功能。

## v0.1 — MVP：新闻到网页和 RSS 的完整闭环

### 里程碑 A：Windows 本地运行环境
- [ ] 初始化 TypeScript 项目、后端与前端目录结构
- [ ] 编写 `.env.example` 与运行说明（不提交真实凭据）
- [ ] 验证 Windows 原生 Codex CLI 安装、登录与 App Server 启动
- [ ] 建立最低限度的自动化测试与 CI

### 里程碑 B：Codex Adapter
- [ ] 使用子进程 stdio 与 App Server 通信
- [ ] 实现 initialize / initialized 握手
- [ ] 支持 thread/start、turn/start、完成事件处理
- [ ] 保存任务关联信息和错误状态；正确区分完成/失败/中断
- [ ] 实现基本超时、取消与进程异常退出处理

### 里程碑 C：基础新闻处理
- [ ] 实现至少一种公开 RSS 来源采集
- [ ] 标准化 URL、来源、发布时间与抓取时间
- [ ] 最简单的 URL 去重和任务幂等
- [ ] 约束 AI 输出为可校验的结构化内容
- [ ] 引用链接检查、来源缺失时拒绝自动发布

### 里程碑 D：阅读与订阅
- [ ] 支持一份日报的 HTML / JSON / RSS 2.0 导出
- [ ] 实现频道列表、日报详情、历史日期浏览
- [ ] 提供频道级 RSS Feed 和订阅入口
- [ ] 本地构建结果可部署到静态托管平台

### v0.1 验收标准
在 Windows 本地执行一次任务，能够：从真实可访问的新闻源采集内容 → 由 App Server 启动 Codex 分析 → 校验输出 → 存储结构化记录 → 生成可用的网页和 RSS 文件。无来源或任务失败时不得发布伪成功内容。

## v0.2 — 任务管理与可观察性

- [ ] 任务创建、编辑、启用、暂停、手动触发
- [ ] 本地持久化调度、漏执行补偿、避免重复执行
- [ ] Agent 运行事件经 SSE 展示在管理后台
- [ ] 历史运行、日志过滤、失败重试、取消
- [ ] 独立的后台认证和配置管理
- [ ] 发布记录与手动重建内容

## v0.3 — 信息质量与频道系统

- [ ] 可配置新闻源与频道模板
- [ ] 跨来源事件合并与相互矛盾信息提示
- [ ] 事实、评论、推断及未经证实内容分级
- [ ] RSS 单条新闻 / 整期日报模式
- [ ] 内容预览、人工审核与自动发布策略
- [ ] 更严格的发布与回滚机制

## 后续候选能力

- 邮件、IM/Webhook 推送
- 全文检索和专题订阅
- 多运行节点、运行资源限额
- 各类内容来源插件
- 自定义 Agent Skill / 分析模板

## 开发约束

- 不在没有真实数据源时伪造生产新闻。
- 不优先搭建重型微服务、消息队列或 Kubernetes。
- 不将 App Server 当作可以直接暴露公网的 HTTP API。
- 不将“使用 ChatGPT 账户登录”理解为无限免费使用。
- 优先 Windows 原生运行；不要求 WSL。
