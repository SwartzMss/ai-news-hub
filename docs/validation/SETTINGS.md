## 自动化

lint、typecheck、build 通过；完整 npm test 为 147 项 Node/公共站 + 17 项 Admin，全通过。未新增运行或开发依赖。

新增后端验证覆盖：

- 仅基础启动配置，生成 0600 本机初始化码，初始化一次后失效；业务接口未初始化为 503、未登录为 401。
- scrypt 密码登录、12 小时会话/过期、退出、轮换撤销所有旧会话；旧 Token 迁移成密码后即使旧 env 残留也无法重新授权。
- 数据库保存/重启、配置 revision 冲突、严格字段/范围、Token 加密不明文入库/不回显、留空保留与显式清除。
- 无效旧 env 在已有 DB 时被忽略；首次导入仍执行校验，Web 修改优先。
- 同源/本机 Host 边界、调用前并发认证限流；缺失加密密钥拒绝启动且不静默生成新密钥。
- 执行时拒绝改设置，新 Turn 使用保存的模型/超时；Web 更换 GitHub 目标后形成独立归档记录，不覆盖历史。

Admin 覆盖首次初始化、登录与既有 Task/Run 导航、内存会话失效、Settings 提交、Token 保留/清除及改密码替换会话。既有任务、审批、取消、归档与公共输出 RSS/静态构建测试继续通过。

## 浏览器

Playwright + Chromium 驱动真实 Fastify 和临时 SQLite。模型、来源 HTML 和 GitHub 写入使用可控模拟，无真实账户/发布副作用：

1. 只配置 HOST/PORT/DATA_DIR，打开 Admin，读取本机初始化码、设置密码进入后台。
2. 系统设置填写 GitHub 仓库/分支/Token、模型及日志级别；保存后 Token 输入为空，刷新重新登录后配置保留。
3. 研究两轮并显式生成待审核报告，人工批准和归档，模拟 GitHub 写入一次。
4. 更新密码，退出后用新密码登录；后端关闭/重启，重新登录后配置仍存在。
5. 390px 页面无水平溢出，pageErrors=0。

原始测试脚本、临时数据库、初始化码与日志仅保留仓库外私有临时目录。没有提交任何真实凭据。

## 独立审查

后端审查发现旧环境变量在 DB 加载前仍被验证，可能让残留值阻止启动；已拆分为三项启动解析 + 按需 legacy 导入，并补“已有 DB + 无效旧 env”回归。复核 8 项配置/认证测试通过，无剩余必修问题。

UI 审查核对初始化、密码/旧 Token、导航取消、Token 保留/清除、revision/busy 和改密码，独立跑 17 项 Admin 测试通过，无必修问题。

## 运维边界

配置保存在私有 SQLite；Token 用自动生成的 settings.key 加密，数据库和密钥必须一起备份。旧环境仅一次性导入后可移除。Codex 账户登录和系统运行身份仍由主机管理，后台不保存 OAuth 文件。没有匿名密码重置、多用户或自动 GitHub Token 续期；有执行/排队/归档时设置修改被拒绝。
